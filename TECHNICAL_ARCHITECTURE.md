## 2. База данных и система хранения

### 🗄️ Движок: Нативная SQLite в Node.js (`node:sqlite`)
Используется встроенный модуль Node.js `node:sqlite` (`DatabaseSync`), не требующий компиляции внешних бинарников через `node-gyp`.
- **Файл БД:** `data/game.db` (в тестах `data/test_verification.db`).
- **Режим WAL (Write-Ahead Logging):** активируется при старте `PRAGMA journal_mode = WAL;`. Чтение не блокирует запись, обеспечивая высокую конкурентность при многопользовательском входе.
- **Синхронность:** `PRAGMA synchronous = NORMAL;` для баланса между скоростью записи и целостностью.

### 📋 Структура таблиц:
1. **`users`** — персонажи и состояние игроков:
   - `username TEXT PRIMARY KEY` — уникальный никнейм.
   - `color TEXT` — цвет аватара игрока в HEX (`#8be9fd`).
   - `x REAL, y REAL, z REAL, rotY REAL` — пространственные координаты и рыскание.
   - `inventory TEXT` — JSON-массив собранных предметов (свитки, ключи, батареи).
   - `discoveredSecrets TEXT` — JSON-массив открытых секретов.
   - `score INTEGER` — очки квеста.
   - `lastSeen INTEGER` — Unix-timestamp последней активности.

2. **`agent_memory`** — персональный контекст диалога для пары `(username, agentId)`:
   - `username TEXT, agentId TEXT` — составной первичный ключ `PRIMARY KEY (username, agentId)`.
   - `knownFacts TEXT` — JSON-массив фактов, которые профессор уже сообщил данному игроку (исключает повторение одного и того же).
   - `turnsCount INTEGER` — счётчик реплик.
   - `affinity INTEGER` — уровень благосклонности профессора к студенту (от 0 до 100).
   - `lastTopic TEXT` — последняя обсуждавшаяся учебная тема.
   - `history TEXT` — JSON-массив последних 10 сообщений диалога (в промпт к LLM передаются последние 4 для экономии токенов).

3. **`quest_progress`** — состояние глобального квеста (Сейф Основателей):
   - `id TEXT PRIMARY KEY` (`'main_quest'`).
   - `completed INTEGER` — флаг открытия сейфа (`0` или `1`).
   - `solvedBy TEXT` — никнейм студента, первым решившего загадку.
   - `solutionCode TEXT` — победный код доступа (`'2327'`).
   - `completedAt INTEGER` — время победы.

4. **`chat_log`** — история общего чата:
   - Хранятся последние 200 сообщений в кольцевом буфере для вновь подключившихся игроков.

### ⏱️ Стратегия автосохранения (Persistence Strategy):
- Все перемещения игроков накапливаются в памяти сервера (`clients Map`) и помечаются флагом `dirty = true`.
- **Таймер каждые 5 секунд:** сохраняет в SQLite позиции только изменившихся (`dirty`) игроков пачкой.
- **Штатное выключение / Отключение:** при `ws.on('close')`, а также сигналах `SIGINT` и `SIGTERM`, сервер принудительно сбрасывает все активные сессии в базу данных.
- **Отказоустойчивость:** если SQLite файл заблокирован другим процессом ОС, активируется прозрачный fallback на `JsonStorage` с атомарной подменой файлов (`gameState.json.tmp` $\rightarrow$ `gameState.json` + `gameState.json.bak`).

## 3. Сетевой протокол и WebSocket

### 🔐 2-этапный защищённый вход (Authentication Gate):
1. **HTTP Handshake (`POST /api/login`):**
   Клиент передаёт никнейм и цвет. Сервер генерирует криптографически стойкий токен:
   $$\text{token} = \text{crypto.randomBytes}(16).\text{toString}('hex') \quad (128\text{ бит энтропии})$$
   Токен регистрируется во временном хранилище `AuthManager`.
2. **WebSocket Gate (`WS /ws`):**
   Клиент устанавливает сокет и первым сообщением обязан прислать:
   `{ type: "AUTH", token: "<token>" }`.
   Любые игровые пакеты (`MOVE`, `CHAT`, `REQUEST_CHUNK`), присланные до успешного `AUTH`, **немедленно отклоняются** сервером с закрытием соединения.
3. **Обработка дубликатов никнейма (Reconnect):**
   Если игрок с таким же ником подключается повторно (например, обновил вкладку), сервер сохраняет позицию старой сессии в SQLite, закрывает старый сокет с кодом `4001 (Replaced by newer connection)`, а новую сессию бесшовно сажает на те же координаты.

### ⚡ 20 Hz State Broadcast Loop:
- Сервер крутит таймер каждые **50 мс** (`TICK_RATE_MS = 50`).
- Собирает снимок всех активных игроков: `[{ username, color, x, y, z, rotY }, ...]`.
- Рассылает широковещательный пакет `PLAYERS_SYNC`.
- **Клиентская интерполяция:** клиент не дергает координаты рывками, а плавно интерполирует позицию удаленных аватаров с помощью линейного сглаживания `Vector3.lerp` со скоростью `delta * 12.0`.

### 📦 Спецификация сообщений:
| Тип сообщения | Направление | Назначение |
|---|---|---|
| `AUTH` | Клиент $\rightarrow$ Сервер | Передача токена авторизации |
| `AUTH_SUCCESS` | Сервер $\rightarrow$ Клиент | Подтверждение входа, метаданные мира, байты чанков, инвентарь |
| `MOVE` | Клиент $\rightarrow$ Сервер | Координаты игрока $(x, y, z, \text{rotY})$ с лимитом 20 раз/сек |
| `PLAYERS_SYNC` | Сервер $\rightarrow$ Клиенты | 20 Гц снапшот координат всех участников |
| `CHAT` / `CHAT_MESSAGE` | Клиент $\leftrightarrow$ Сервер | Командный чат с фильтрацией длины ($\le 250$ символов) |
| `PROP_PICKUP` / `PROP_PLACE` | Клиент $\leftrightarrow$ Сервер | Подбор и перестановка предметов на полу |
| `PROP_THROW` / `PROP_THROWN` | Клиент $\leftrightarrow$ Сервер | **Сетевой бросок предмета с вектором начальной скорости** |
| `CLIENT_TELEMETRY` | Клиент $\rightarrow$ Сервер | **Телеметрия клиента:** FPS, Ping (мс), загруженные чанки, RAM |
| `PING` / `PONG` | Клиент $\leftrightarrow$ Сервер | Замер задержки сети (Round-Trip Time) |
| `WORLD_MUTATION` | Сервер $\rightarrow$ Клиенты | **Динамическое изменение 3D-мира:** световые маяки, серверы, порталы |
| `WORLD_SETTINGS_CHANGED`| Сервер $\rightarrow$ Клиенты | Изменение гравитации, тумана, света из админки |

## 4. Стриминг чанков и строгое ограничение кэша ($\le 10\%$)

### 🗺️ Мир 10×10 секторов (100 чанков):
- Карта кампуса разбита на сетку $10 \times 10$ секторов (координаты $cx \in [-5..4], cz \in [-5..4]$).
- Размер одного сектора: $24 \times 24$ игровых метра.
- Центр кампуса (сектора вокруг $(0,0)$) занимает интерьер Главного учебного корпуса (холл, лаборатория сетей ИУ-5, обсерватория, библиотека). Внешние сектора — внутренний двор и фасады.

### 📏 Канонический расчёт байтовых размеров без полного скачивания:
Сервер при старте канонически рассчитывает UTF-8 сериализацию каждого чанка:
- Ключи JSON сортируются по алфавиту для детерминизма.
- Измеряется точная длина байт:
  $$\text{byteSize} = \text{Buffer.byteLength}(\text{canonicalJson}, 'utf8')$$
- При входе сервер сообщает клиенту: `totalWorldBytes` ($\approx 52\text{ КБ}$).
- При получении чанка клиент получает: `chunkBytes` и `byteSize`.

### 🧠 Клиентский LRU / Distance Cache ($\le 10$ чанков):
- Клиент отслеживает текущий сектор игрока: $cx = \lfloor (x + 12)/24 \rfloor$.
- Подгружает активное окно $3 \times 3$ вокруг игрока (9 секторов).
- **Лимит кэша:** строго $\le 10$ чанков ($10\%$ от 100 чанков мира).
- **Сборщик мусора (GC):** при превышении 10 секторов самый удаленный от игрока сектор полностью уничтожается:
  - Вызывается `geometry.dispose()` для всех мешей пола, стен и перекрытий.
  - Удаляются динамические холст-текстуры надписей.
  - Общие материалы (дерево, мрамор, гранит) переиспользуются через глобальный пул материалов `materials.js` для предотвращения утечек памяти GPU.

```
[Запрос игрока]
       │
       ▼
```

## 6. Физический движок твердых тел (`physics.js`)

Клиентский физический движок реализует реалистичную механику взаимодействия с миром:

### 📐 Уравнения движения:
1. **Баллистический бросок с инерцией:**
   Начальная скорость брошенного предмета складывается из импульса броска и скорости движения персонажа:
   $$\vec{v}_0 = \vec{v}_{\text{look}} \cdot F_{\text{throw}} + \begin{pmatrix} 0 \\ 2.2 \\ 0 \end{pmatrix} + 0.85 \cdot \vec{v}_{\text{player}}$$
2. **Гравитация и сопротивление воздуха:**
   $$\vec{v}_{t+\Delta t} = (\vec{v}_t + \vec{g} \Delta t) \cdot (1 - k_{\text{drag}} \Delta t), \quad \text{где } \vec{g} = (0, -9.8 \cdot \text{gravityMultiplier}, 0)$$
3. **Упругий контакт с полом ($y \le y_{\text{floor}}$):**
   При соударении с поверхностью пола вертикальная скорость отражается с коэффициентом восстановления:
   $$v_y' = -v_y \cdot e \quad (e = 0.55)$$
   Горизонтальные составляющие скорости тормозятся кулоновским трением:
   $$v_x' = v_x \cdot \mu, \quad v_z' = v_z \cdot \mu \quad (\mu = 0.72)$$
4. **Вращательное кувыркание:**
   В воздухе предмет хаотично кувыркается по осям с вектором $\vec{\omega}$. При каждом отскоке угловая скорость гасится: $\vec{\omega}' = \vec{\omega} \cdot 0.65$. При снижении $|v| < 0.15$ м/с предмет плавно засыпает (`RESTING`).
5. **Дверные петли:**
   Интерактивные двери рассчитываются через гладкий угловой регулятор скорости с ограничением максимального угла распахивания $86^\circ$.

## 7. Составные анимированные 3D-объекты (`animatedProps.js`)

Все сложные объекты собраны из иерархических узлов Three.js:
1. **Напольные часы Бауманки (`GrandfatherClock`):**
   - Корпус из темного ореха с резным карнизом и смотровым стеклом.
   - Маятник: гармонические колебания $\theta(t) = 0.24 \cdot \sin(3.2 \cdot t)$.
   - 2 зубчатые шестерни за стеклом: противовращение согласно передаточному отношению $14:10$.
   - Циферблат: независимый ход минутной и часовой стрелок.
2. **Обсерваторный телескоп (`ObservatoryTelescope`):**
   - Треножный штатив.
   - Азимутальная турель: плавное круговое сканирование сектора неба.
   - Труба элевации: вертикальный наклон $\sin(0.35 t)$.
   - Фокусировочный маховик: непрерывное вращение.
   - Оптическая линза: синусоидальная пульсация свечения `emissiveIntensity`.
3. **Арканный гироскоп (`ArcaneGyroscope`):**
   - 3 концентрических карданных кольца вращаются независимо вокруг осей $X, Y, Z$.
   - Центральный кристалл: левитация по вертикали и дыхание масштаба $1.0 + 0.12 \sin(5t)$.
4. **Серверная стойка ИИ (`AnimatedServerRack`):**
   - 24 независимых разноцветных светодиода с псевдослучайными фазами мерцания.
   - 2 скоростных вентилятора охлаждения ($15\text{ рад/с}$).

## 8. Экосистема реактивных мобов (`reactiveMobs.js`, `server/mobs.js`)

По территории кампуса распределены **40 реактивных NPC** (без тяжелых внешних 3D-файлов):
- **15 Летучих мышей (`ReactiveBat`):** кружат под потолком с частотой взмахов крыльев 12 Гц. При приближении игрока или включении фонаря (`KeyL`) переходят в состояние `FLEE`: учащают взмахи до 24 Гц и взмывают вверх к стропилам.
- **15 Призрачных кошек (`ReactiveSpectralCat`):** сидят на лавках и подоконниках. При приближении игрока активируется **динамический трекинг шеи**: кошка поворачивает голову и провожает игрока взглядом (`lookAt`). При спринте (`Shift`) игрока кошка пугается и прижимается к полу.
- **10 Бродячих теней студентов (`ReactiveShadowStudent`):** парят между книжными шкафами с левитирующим гримуаром. При разговоре в чате или с профессором тень останавливается, поворачивается лицом к говорящему (`state = 'LISTENING'`) и внимательно слушает.

## 9. Панель администратора (`/admin`)

Панель выполнена в стиле Cyberpunk Glassmorphism и доступна по адресу `http://localhost:3001/admin`:
- **Живая телеметрия игроков:** таблица с автообновлением 1.5 сек (Никнейм, IP, FPS, Ping, Чанки, Память RAM).
- **Слайдеры мира:** изменение плотности тумана ($0.005 - 0.08$), силы света ($0.2 - 2.5$), гравитации ($1.0 - 20.0\text{ м/с}^2$), типа погоды.
- **1-Click пресеты:** «Луна (низкая гравитация)», «Хэллоуин (мистический туман)», «Ясный день», «Сверхтяжесть».
- **Управление агентами:** переключение настроения профессоров (`normal`, `helpful`, `strict`) и редактирование системного промпта на лету.
- **Кнопки мутаций:** мгновенный призыв небесного луча света к Сейфу, серверной стойки или портала.
- **Глобальный анонс:** отправка широковещательного баннера во все подключенные браузеры.
