# Ночь в Бауманке — готовая игровая версия

## Запуск

`npm install` → `npm run build` → `npm start`. Игра: http://localhost:3001/, админ-панель: http://localhost:3001/admin. Для разработки — `npm run dev` (5173), отдельная прогулка — `npm run walk` (5174). Старый павильон сохранён в `/pavilion.html`.

## Сценарий

В здании три спектральных преподавателя: Канев Константин Юрьевич у правой лестницы, Коршунов В.М. в правом коридоре, Масленников в левой галерее. Каждый задаёт три вопроса с вариантами ответов. Неверный ответ не продвигает квест. Три правильных ответа дают зачёт и награду в журнале. Три зачёта вызывают экран победы и открывают портал знаний. Человеческая модель преподавателя в игровой сцене убрана; отдельное старое превью сохранено.

Допуск Канева открывает учебную аудиторию в горизонтальном коридоре. Дверь имеет анимацию и коллизию. Часы и гироскоп состоят из движущихся деталей. Три предмета можно брать, ставить и бросать с инерцией и отскоками. В здании 42 реактивных неагентных NPC: 16 мышей, 16 котов, 10 теней студентов. Видимость ограничена расстоянием; движения и реакции в сетевой сессии получают общее состояние сервера.

Окружение оформлено тыквами, свечами, гирляндами и светлячками. В настройках доступна яркость. Герб загружен локально с https://oris.bmstu.ru/assets/img/bmstu-logo.svg и используется в шапке, залах и на экране победы.

## Сетевая часть

Кнопка подключения использует существующие HTTP login/register и WebSocket AUTH. Затем клиент отправляет CAMPUS_JOIN, чтобы отделить карту Бауманки от прежнего павильона. Сервер проверяет ответы, выдаёт награды и сохраняет прогресс. CAMPUS_MOVE синхронизирует игроков, CAMPUS_DOOR — общую дверь, CAMPUS_PROP — переноску/броски/финальное положение предметов. NPC получают общее состояние каждые 300 мс. Положение игроков передаётся с частотой до 20 Гц, на клиенте есть интерполяция.

Через диалоги можно попросить «темно, освети дорогу», «нужна серверная стойка», «открой портал». Классификатор намерений сразу создаёт общее изменение мира, затем отвечает локальная LLM или резервный алгоритм. Последние сообщения и учебные действия хранятся в памяти агента в SQLite и передаются как контекст следующего ответа.

На `/admin` доступны живые FPS/ping, память и draw calls, изменение гравитации/тумана/света, поведения и имени преподавателей, создание объектов и уведомления. Состояние дверей, предметов, изменений мира, настройки администратора, прогресс и координаты записываются в SQLite через существующую таблицу quest_progress с отдельными ключами. Память диалогов — agent_memory. Онлайн-прогресс проверяется сервером; одиночный режим хранит прогресс в localStorage `bauman-session-v2`.

Сцена здания загружается целиком и использует InstancedMesh. Для неё не заявляется секторный лимит 10% старого павильона. В админ-панели это отмечено как статическая карта.

## Управление

WASD / стрелки — ходить, Shift — быстрее, мышь — осмотр, E — взаимодействие, G — взять/поставить, F — бросить, L — фонарь, J — журнал, M — карта, Enter — чат, Tab — скрыть панели, Esc — курсор/закрыть диалог, R — к началу.

## Проверки

`node --test test/campusQuest.test.js test/campusServer.test.js` проверяет отказ в зачёте за ошибки, три правильных ответа, победу и восстановление локального прогресса. Браузером проверены два клиента, девять ответов, награды, отсутствие ошибок JavaScript, движение второго игрока, общая дверь, реакция мира на запрос агента, телеметрия и изменение гравитации из админ-панели. Сборки: `npm run build`, `npm run build:walk`.

Габариты здания восстановлены приблизительно. Учебная аудитория — игровая интерпретация пространства за дверью. Для мультиплеера нужно подключиться к серверу; одиночный режим предназначен для прогулки и локального прохождения.
